# 预注册对照协议

本轮使用原创合成案例，先冻结任务与评分规则，再读取新版本输出。条件为无 Skill、旧正式版、新候选版；三个作者共用任务。每种条件一次执行同一批任务，各题明确相互独立。C09另开独立进程，传入该条件C05的真实输出与用户反馈。此方式是显式重放对话，不宣称检验了产品内持久会话。

模型、推理档、CLI版本和启动命令固定并记录；每次全新临时工作目录；不给模型访问项目研究结果，不使用工具或联网。旧版使用完整便携版，新版使用完整生成便携版；无Skill不附加创作者规则。同一条件批量作答降低成本，也可能产生题间影响；不将其冒称逐题独立随机试验。单次采样、同模型裁判、小样本，不能给出统计显著性或普遍胜率。

输出保留原文，评分副本隐藏版本、路径、创作者名称，以固定随机种子为每题打乱A/B/C标签。裁判只看任务、事实、输出及下列标准，不看Skill与作者审计。标签映射在评分完成后才解盲。写作细节可能暴露方法，因此是版本身份遮蔽而非严格双盲。

每项0—4分：0严重失败；1主要问题；2部分满足；3满足且有轻微缺口；4充分满足。七项为：切中任务、方法适配、可执行性、事实与经验诚实、避免强套模板、保留用户表达和范围、约束完成度。以具体输出片段或缺失说明每项扣分，不因篇幅长、术语多、出现某个标题而加分。第七项用于可观察约束，不把“比旧版好”当单个输出评分标准；升级是否有实质提升由解盲后的成对差异判断。

同时核查cases.json中的事实与范围条件；至少人工复核旁白、定向修订、反馈、技术结论、非适用边界的真实输出。新候选退步时先记录失败，再做最小修复并用原案例与未见过的邻近案例回归。修复输出另存，不覆盖失败。安装/链接/打包检查单独报告，不能替代创作行为评测。

跨风格混淆：比较三套方法对C01、C03、C04、L01、M01的决策及证据选择；通用诚实原则相同不算混淆，结构与决策无差别且抹去领域能力才算。保留评分与文字依据，不以字符串差异宣称方法差异。

发布判定：安装结构与引用必须可用；不得新增重大事实虚构；至少指出实际改善、持平与退步。若质量未优于旧版，应标注候选局限，不能仅凭格式检查宣布升级成功。
