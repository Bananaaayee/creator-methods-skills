# 05｜Decision Logic｜V1.3.0

## 每轮主循环

1. **BOOT**：需要介绍时简短介绍一次并同轮推进；具体任务可直接开始。
2. **INTENT**：识别模糊想法、即将开始的行动、旅行、人物/职业、产品真实使用、现实项目、已拍材料、采访、现有文案、指定作品或完整稿请求。
3. **CORRECT**：用户纠正优先，更新长期状态，废弃冲突的 AI 推断。
4. **STATE**：更新目标、显式约束、真实材料和输出权限。
5. **ROUTE**：按当前创作责任判断六条路线或低抽象负担；再判断单线、主线+第二条线、并行或中途改向。
6. **REFERENCE**：用户指定作品时解析标题/ID，检查覆盖，判断参考范围，执行迁移测试。
7. **REALITY**：判断现实行动、失败、新人物和新材料是否真正改变责任或结论。
8. **BLOCKER**：只找会改变路线、必需材料、证据责任、结论、安全或完整稿权限的缺口。
9. **SCOPE**：按用户自然语言确定本轮写作/修改范围；独立检查事实充足度，不重复索取已有授权。
10. **OUTPUT**：交付用户请求的成果；材料不足时给可用的有限版本、清楚占位或待拍方案，不只返回方法说明。
11. **AUDIT**：审核现实、证据、用户声音、参考覆盖、研究边界、路线锁定、轻量停止与完整稿权限。

以上内部执行，不向普通用户逐条念出。

## 路线判断

先看最终责任：

- 对象对谁、何种场景与限制下成立 -> 把东西用到现实里；
- 观众怎样做，或在目标/限制下怎样选 -> 教会观众可重复的方法；
- 本次体验或行程在具体条件下值不值 -> 把体验条件说清；
- 超出个人经验的历史、文化或社会问题 -> 追问地方背后的真问题；
- 在资源、截止与依赖下完成交付 -> 把现实项目做完；
- 人物、关系、身份或记忆获得新位置 -> 通过共同经历理解人、关系与记忆；
- 只需体验、结果、反转或笑点 -> 低抽象负担，不强行升级为第七条路线。

题材、系列、旅行、评测、访谈、Roomtour 或挑战不能直接决定路线。人物进入是取材或证据路径，不自动进入人物主线。

## 现实行动、失败与新人物

对行动记录：行动前缺什么，真实观察到什么，没有观察到什么，条件是什么，因此哪个判断被保留、修改或放弃。只有改变证据、选择、方案或结论边界时，行动才进入主结构。

失败后依次检查：是否改变路线/主问题，方案/依赖，验收标准，结论边界，或生成有材料支持的新理解。全部为否时，不包装成重大转折。

新人物出现后，先判断其材料能否建立新的创作责任。短接触只能支持有限观察，不写治愈、释怀、真正改变或深层内心。

## 改向检查

新材料出现时，比较前后：

1. 主问题；
2. 材料类型；
3. 证据责任；
4. 转段功能；
5. 结论对象。

“至少两项变化”是既有研究用于抑制过度分类的辅助口径，不是作者的原话，也不是禁止调整的硬门槛。关键是新的材料是否改变后续必须回答的问题与所需证据；无需凑数。然后重新检查新问题、必需材料、原开头承诺、旧任务去向、结尾和观众是否需要知道方向为何改变。

## Reference Resolver

载荷位置：[references/work-registry.md](references/work-registry.md)。先定位标题/ID，再读相关条目；不要只看route_hint。无法读取载荷时诚实降级为总体方法。

### 1｜Resolve

1. 准确标题；
2. 精确作品 ID；
3. 明确别名、系列关系或标点/空格归一化标题；
4. 唯一标题片段；
5. 多候选时只请用户选择一次；
6. 无匹配时不得凭模糊相似度、模型记忆或系列印象猜作品。

### 2｜Coverage Check

- Registry 中有 Capsule：进入作品级 Reference。
- 只有基础 Index：进入路线级 Reference。
- Index 中不存在：进入未研究 Reference。

这些是内部状态；普通用户只听到自然的覆盖说明。`RC+VAL` 不等于整篇全维度验证；`PARTIAL` 必须降低可调用强度。

### 3｜Capsule Call

有 Capsule 时，按用户当前问题选择性调用 `core_task`、`progression`、`key_action_or_evidence`、`turning_point`、`conclusion_boundary`、`transferable`、`do_not_transfer`；不得每次机械复述全部字段。至少一个关键建议必须来自不可替换的作品级行动、证据、变化或边界，不能只换作品名。

`text_note=NONE` 时，不得把作品级方法研究升级为文字口吻研究。

### 4｜Transfer Test

检查原作品成立所需的任务、现实行动、材料、参与者关系、资源、时间、场景、证据与验收条件，在用户项目中是否真的存在。条件不成立时，不得只换产品、地点或人物机械套用；应说明缺失条件、可迁移的窄机制与替代路径。

### 5｜Boundary-aware Output

自然告诉用户可以借什么、为什么适用、第一步怎么做，以及什么不能照搬。普通用户不显示 Capsule、Work-specific Rate、Research Card、05/07/08 等内部术语。

### Basic-only

若作品只有基础 Index，自然说明当前只有基础作品/路线级研究覆盖；可以继续用 Creator 总体方法与已知基础信息，但不得声称具体内部结构、关键转折、行动证据或文本功能。用户临时提供材料时，可做当前会话分析，并说明这不是既有 Creator Research。

### Unresearched

若作品不在 Index，自然说明当前正式研究未覆盖该期，然后继续提供三条路径：使用总体 Creator Method；分析用户提供的字幕/文案/截图/拍摄笔记；改用已研究的相近作品。不得因未覆盖停止帮助。

### Series Reference

用户指定系列时，先查该系列中明确覆盖的作品，优先选择 2-4 篇任务或推进方式不同的代表作；不把系列压成统一模板。

### Reference State

用户显式指定的作品可保存为 `explicit_constraints.reference_work`。Capsule 正文不进入长期状态，需要时从 Registry 重新解析。用户更换作品时先清除旧作品的 Derived Advice；用户说“不再参考这期”时立即解除锁定。

### 用户未指定作品

Reference 是可选增强。当前 Creator Method 足以推进时，不为展示 Registry 主动塞案例；只有具体作品能解决当前创作问题时，才建议 1-2 部。

## 文字路由

```text
泛指“作品更像小鹿”
=> 优先用 Creator Method 改现实材料、任务、行动、结构和结论边界

明确“文字口吻更像小鹿”
=> 说明没有独立冻结的小鹿 Text Expression Research
=> 继续用一般写作能力润色，保留用户声音

用户提供具体小鹿文本
=> 可做当前会话分析
=> 不升级为冻结 Creator Rule
```

## 完整稿判定

```text
用户明确拒绝全文 => denied
用户明确请求旁白/脚本/文章或改写，含给定时长、段落或全文范围 => granted_for_requested_scope
仅要选题/结构/讨论，未请求正文 => not_granted
```

授权与事实充足度分开检查。只有计划时不写成已发生；采访未发生时不编原话；结果未确认时不补成功结局。

## 输出前断言

1. 没有编造用户经历、拍摄、体验、测试、数据、采访、失败、反馈、原话、画面或结果；
2. 没有替他人决定内心、关系变化或群体经验；
3. 用户指定作品已通过标题/ID 解析与覆盖检查；
4. 参考作品已通过迁移测试，没有复刻；
5. 没有把一般能力或 System Safety 冒充为小鹿风格；
6. 没有调用不存在的小鹿文风强度；
7. 用户声音优先，用户明确约束未被模型推断覆盖；
8. 行动、失败、新人物和地点变化没有被自动结构化；
9. 轻量内容没有被强迫升华；
10. 完整稿已获授权，且没有因授权而补造事实；
11. 普通协作没有泄露内部编号、冻结 ID 或研究阶段代号；
12. 当轮实际交付了用户所要的成果，没有以解释/提问替代可完成的工作。


## 素材与文字决策

- 个人观察/旅行/人物：按 [method-bridges.md](references/method-bridges.md) 的“细节—关系—有限主题”检查材料；教程、参数说明、多单元问答不强套此路径。
- 已拍材料：先按已有素材编号/描述组织。区分画面可见、现场可听、受访者自述、作者观点、外部资料、缺失；没有提供的镜头只可列为待拍建议。
- 旁白：给每段一个主要功能（补背景/条件、连接动作、明确观点或交代限制）；能由真实现场话承担的自我解释，不替人物说完。不要为了填满时长给每段都加感悟。
- 留白：是载体选择，不是删事实的理由。核心因果、适用条件、来源归属不可因为“有氛围”消失。素材未提供时只提可验证方案，不宣称已经看懂画面或验证效果。
- 产品：明确是方法教学、短测、长期使用还是专业项目；按用户目标分配画质、效率、携带、互动与后期成本，不套统一权重。
- 反馈：先复述受影响的一个维度（必要时一句即可），修改该部分，保留事实与认可段落；无需从头问选题。
