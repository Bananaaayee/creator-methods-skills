- 模块化安装：把本包 `skill/` 整个文件夹复制到支持 SKILL.md 的安装目录，并命名为 `media-storm-creator`；保留其中六个模块和 references。安装识别与实际创作质量是两项检查。
- 上传 ChatGPT：上传本包 dist 中的单文件 Markdown；这是一份可携带的工作指令，不保证不同平台自动注册为原生插件。上传后直接提出创作任务，或先说“检查技能状态，不开始创作”。
- 新增独立的现场可控程度判断：讲述/可重复测试可以先拟问题；现场观察不预设反应，已有素材从实际事件形成主线。
- 产品材料分清展示、条件测试、机制论证、场景样片；没有测试结果可以写计划或保守介绍，不能借样片补出性能结论。
- 只改文字时跳过创作路由；局部修改不重做项目。用户请求完整稿、300字旁白或指定段落本身即授权该范围。
- 旧版七工作流、作品解析、72 Capsule、440 基础索引和研究降级保留；大作品库移到按需 references，单文件仍携带全部必要载荷。新增证据按命题记录，不升级整个作品的历史覆盖标签。

以下是继承并更新版本的完整指南。其方法示例中的产品规格和行业状态属于作品当时的研究内容，不能作为今天的购买事实；实际创作需另核当前信息。

# 影视飓风 Creator Skill V1.22.0｜完整使用指南

> 独立研究工具 · 非官方产品  
> 创作方法 · 工作流 · 文字表达

# 1. 这是什么

影视飓风 Creator Skill 是一个基于公开作品研究整理出的创作决策与内容协作工具。

它不会先按“科技、旅行、评测、纪录片”套模板，而是先和你确认：这期最后到底要判断什么、解释什么、做成什么，或者真正理解什么。然后再决定需要哪些材料、现实行动、证据、结构和结论。

它也不是“影视飓风风格生成器”。它迁移的是创作责任、研究方法、证据组织和文字表达机制；最后做出的仍然应该是你的作品。

> 这不是 Tim 或影视飓风官方发布、授权或背书的产品。首次加载直接处理已有任务；未给任务时仅简短提示可以提供想法、素材、结果或现稿。

# 2. 30 秒开始

普通用户只需要加载：

```text
dist/media-storm-creator-skill-v1.22.0-portable.md
```

然后直接说自己的项目：

```text
我想做一期 iPhone X。先帮我确定这期真正要回答什么，不要急着写完整稿。
```

Skill 会先判断任务与证据，不会要求你先学习内部术语，也不会一上来让你从七个工作流里做选择题。

如果你已经有结果：

```text
我已经拍完并完成测试。这里是实际结果，请让结果决定结构和结论，不要补写我没做过的事。
```

# 3. 普通协作与进阶协作

## 3.1 普通协作：默认方式

直接自然聊天即可。适合绝大多数用户。

- 不需要知道工作流；
- 不需要理解研究覆盖；
- 不显示控制面板；
- Skill 在内部判断任务、证据、规模与下一步；
- 意图已经清楚时直接推进，只问真正影响路线的问题。

## 3.2 进阶协作：需要时再打开

当你想精确控制工作流、主线与副线、参考作品、证据、规模、结构、文字或完整稿时，说：

```text
进入进阶协作。
```

进阶协作可以显示：当前主工作流、副线、工作线关系、参考作品、研究支持、证据缺口、内容规模、结构控制、文字表达和完整稿权限。

退出时说：

```text
回到普通协作。
```

启动时不需要选择模式。普通协作永远是默认。

## 3.3 常用控制句

| 你想控制什么 | 可以直接这样说 |
|---|---|
| 指定工作流 | 这期明确按产品判断做，不要做成机制科普。 |
| 指定主副线 | 产品判断是主线，机制解释只能做副线。 |
| 指定参考作品 | 我想参考《XXX》，但不要照抄内容。 |
| 查看研究支持 | 告诉我你对这期参考作品研究到了什么程度。 |
| 保持轻量 | 这期保持轻量，证据不够就缩小结论。 |
| 保持结构 | 结构不动，只处理局部问题。 |
| 只改文字 | 只改文字，不动结构和结论。 |
| 停止完整稿 | 先别写完整稿，只给任务、证据和结构。 |

# 4. 你可以直接怎样开始

## 4.1 只有一个模糊想法

```text
我想拍一台旧手机，但还不知道这期为什么值得做。先帮我找一个真正的任务。
```

Skill 会判断它更适合产品判断、机制解释、项目交付、人物或其他责任，而不是马上写一个通用评测脚本。

## 4.2 已经确定选题

```text
我的题是“2017 年的旗舰，今天还能承担什么角色？”请设计最低成本、但真的会改变判断的测试。
```

## 4.3 已有材料

```text
这是我现有的资料。先区分品牌说法、直接测试、第三方数据和推断，再告诉我真正缺什么。
```

## 4.4 已经拍完或测完

```text
不要替我补结果。请根据真实结果调整论证，把没有被支持的结论删掉。
```

## 4.5 已有结构

```text
保持当前结构。只指出证据断点，并给局部修补方案。
```

## 4.6 已有文案，只想改文字

```text
结构和事实都不动。保持我的口吻，只加强技术解释和结果限定。
```

# 5. 我们到底从影视飓风研究出了什么？

大量作品研究最后换来的，不是一个需要用户背诵的模型，而是几种很具体的创作能力。

## 5.1 先找到这期真正负责什么

同样是“拍一个产品”，可能是在做采用判断，也可能是在解释技术、完成真实任务，甚至借这个产品理解一段个人经验。Skill 会先找终点，再决定结构。

## 5.2 让现实行动真正产生作用

实验、测试、采访、旅行、制作和资料不是为了看起来专业。它们应当改变你能知道什么、下一步怎么选、作品是否完成，或者结论能下多大。

## 5.3 让真实结果改写作品

现实结果和预想不同，可以改路线、改结构、缩小结论，或承认失败与负结果。不会让现实去配合已经写好的文案。

## 5.4 把技术与证据翻译成人能理解的后果

参数与术语只有在会改变理解、行动、风险、成本或最终判断时才值得进入正文。品牌说法、受访者观点、直接测试、数据和推断也会被分开处理。

## 5.5 允许作品保持轻量

窄问题、一次真实测试、一个小成果或一段清楚解释，都可以完成作品。研究不会要求每一期都升级成大制作。

## 5.6 用文字帮助理解，而不是复制口头禅

文字层可以改善问题推进、技术解释、信息组织、局部结算、结果限定和文字节奏；不会复制某一期标题、台词或人格。

# 6. 七种核心工作流：先用作品看懂

工作流不是影视飓风官方栏目分类，也不是用户必须先选的菜单。它描述的是一条片最后承担的创作责任。

| 工作流 | 影视飓风真实作品 | 这个例子让你理解什么 |
|---|---|---|
| 1｜产品 / 工具适用性判断 | 《顶配M1 Max挤爆牙膏！近五万的价格到底香不香？2021 MacBook Pro评测》 | 不把参数念完，而是把性能放进真实制作流程，最后判断适合谁。 |
| 2｜机制解释与验证 | 《拍了张照就坏了？激光是怎么破坏摄像头的？》 | 破坏设备只是取证，终点是解释损伤机制与成立条件。 |
| 3｜项目实现与交付 | 《被公司送去格鲁吉亚拍星空？花超预算连夜跑路！》 | 旅行只是外壳，真正任务是在约束下完成样片与短片交付。 |
| 4｜职业现场与劳动链 | 《比电影更夸张？专业保镖到底在做什么？》 | 电影想象只是入口，核心是职业的工序、判断、风险与责任。 |
| 5｜产业 / 公共系统调查 | 《非洲淘金，一场黄金背后的生死赌局。》 | 地点和人物不是终点，要把资源、劳动、交易、规则与代价连起来。 |
| 6｜方法 / 机制拆解 | 《靠剪接就能颠覆电影行业？蒙太奇到底有啥魔力》 | 不只讲概念，还要解释方法怎样运作、何时能用、边界在哪里。 |
| 7｜主体理解 | 《对话导演陆川：花300多天拍野生动物纪录片，为什么？》 | 方法可以迁移，但人的长期选择与价值判断不能被随意替换。 |

下面继续拆开七种工作流。你可以直接指定，也可以让 Skill 自动判断。

# 7. 详细理解七种工作流

## 7.1 产品 / 工具适用性判断

**你可能会问：**这个东西到底适不适合我？

真正要完成的是条件化采用判断：谁用、在什么场景用、什么失败不能接受、替代方案是什么、代价与未验证区域在哪里。

### 影视飓风实际例子

**作品：**《顶配M1 Max挤爆牙膏！近五万的价格到底香不香？2021 MacBook Pro评测》

**这期真正负责什么：**把设计、交互、转码、播放、渲染和移动 HDR 工作流测试汇入采购判断。

**关键研究观察：**短测试期、软件优化差异和未来插件/系统问题会限制结论；生产工具的工作流成本与可靠性会直接改变购买判断。

```text
我想按产品判断来做，但不要沿用原视频关注点。先帮我确定这期最终要判断什么，以及哪些测试会真的改变决定。
```

## 7.2 机制解释与验证

**你可能会问：**这个现象为什么发生？什么条件下会发生？

真正要完成的是一条能被证据支持、能看到反条件的解释链。演示不自动等于验证。

### 影视飓风实际例子

**作品：**《拍了张照就坏了？激光是怎么破坏摄像头的？》

**这期真正负责什么：**解释激光损伤传感器的条件，并用不同距离、设备、波长与结构材料收窄机制。

**关键研究观察：**“大部分激光雷达我们目前测下来都是安全的”把结论限制在当前测试范围。消费者维权或眼睛安全需要不同来源，不能从传感器损伤直接外推。

```text
先说明每个测试要区分什么解释，再把参数接到风险和行动建议，不要做百科全书。
```

## 7.3 项目实现与交付

**你可能会问：**能不能真的把它做成？

真正要完成的是可验收结果，并解释 Brief、约束、修订、成本与仍不完美的部分。

### 影视飓风实际例子

**作品：**《被公司送去格鲁吉亚拍星空？花超预算连夜跑路！》

**这期真正负责什么：**在时间、天气、预算和比赛条件下完成样片与短片交付。

**关键研究观察：**风、交通、预算和设备损失之所以重要，是因为它们改变拍摄对象、路线与完成标准。字幕能验证任务与自评，不能单独验收成片画质。

```text
先定义必须带回什么、最低交付标准、谁验收，以及失败后哪些替代仍算完成。
```

## 7.4 职业现场与劳动链

**你可能会问：**这个职业实际怎样工作？风险和责任在哪里？

真正要理解的是工序、交接、判断、技能、时间与身体成本、风险、伦理和责任。

### 影视飓风实际例子

**作品：**《比电影更夸张？专业保镖到底在做什么？》

**这期真正负责什么：**让电影想象退到真实职业训练、任务判断和风险责任之后。

**关键研究观察：**主持人的参与可以暴露技能差距，但不能代表职业普遍性；采访在这里是职业取证，不自动变成人物片。

```text
我要理解这个职业，不做猎奇体验。请把真实任务、工序、技能、风险和从业者纠正排成证据链。
```

## 7.5 产业 / 公共系统调查

**你可能会问：**这么多人、资源、规则和利益怎样连成一个系统？

真正要完成的是主体位置、资源与权力流向、规则历史、后果、代价归属和证据缺口。

### 影视飓风实际例子

**作品：**《非洲淘金，一场黄金背后的生死赌局。》

**这期真正负责什么：**沿黄金进入资源、劳动、交易、风险与规则构成的系统链。

**关键研究观察：**系统级结论需要多主体与尺度匹配的来源；强烈现场个案不能单独证明更大范围的普遍性，部分宏观判断仍需更强证据。

```text
不要只收集几个动人故事。先画出主体、资源、规则、利益和代价，再告诉我哪些位置还没有证据。
```

## 7.6 方法 / 机制拆解

**你可能会问：**这套方法为什么有效？别人怎样迁移？

真正要完成的是一个可理解、可使用，并带着适用条件、分支与例外的方法模型。

### 影视飓风实际例子

**作品：**《靠剪接就能颠覆电影行业？蒙太奇到底有啥魔力》

**这期真正负责什么：**从定义、历史和电影例子解释蒙太奇，并把解释带到可应用的方法。

**关键研究观察：**文本承认分类没有统一标准，只选择常见类型；历史主张和分类选择仍需区分来源强度。

```text
把这个方法拆成输入、关键选择、步骤、失败条件和迁移边界，不要只列技巧。
```

## 7.7 主体理解

**你可能会问：**这个人、地方、组织或我自己，为什么成为现在这样？

真正要形成的是对不可替代主体的有边界理解。换掉主体后，核心结论应明显损失。

### 影视飓风实际例子

**作品：**《对话导演陆川：花300多天拍野生动物纪录片，为什么？》

**这期真正负责什么：**通过长期观察、剪辑、真实标准、AI 边界和继续做纪录片的理由，同时理解导演本人和可迁移方法。

**关键研究观察：**抽掉陆川，部分纪录片方法仍成立，但长期选择与价值判断会损失。因此人物理解可以是主线，方法拆解是副线。

```text
人物理解是主线，方法拆解是副线。分别告诉我两条线各需要什么材料，不要让方法清单吞掉人物。
```

# 8. 一条视频有两条线怎么办

复杂作品不一定只有一个任务。Skill 支持四种工作线关系。

| 工作线 | 怎样理解 | 简短例子 |
|---|---|---|
| 单一主线 | 所有材料共同完成同一个终点 | 模拟案例：一次旧手机测试，全部证据只回答“今天还能否作为备用机”。 |
| 主线 + 副线 | 副线解释或补证，但不承担最终验收 | 产品判断为主，机制解释只说明为什么某项差异会改变采用决定。 |
| 双线并行 | 两条线各有问题、证据、推进与结果 | 研究案例：《对话导演陆川……》可以分别结算人物理解和纪录片方法。 |
| 主线转移 | 现实结果让最终问题、证据与结论责任一起改变 | 模拟案例：原计划做新品评测，真实测试发现安全异常，作品转为机制验证；必须说明转移证据。 |

仅仅换地点、换语气、加一段采访或加入幽默，不足以证明主线改变。

进阶协作中可以直接说：

```text
产品判断是主线，机制解释只能做副线。
```

# 9. 怎么参考某个系列或某一期

参考影视飓风作品只是可选入口。最重要的默认用法仍然是带着你自己的想法、问题、项目和材料来。

## 9.1 指定工作流

```text
这期明确按项目交付做。最后必须真的完成一个结果。
```

## 9.2 指定系列或内容类型

```text
我想参考“去一趟”这一类作品做山东，但先帮我判断我的题真正该走哪条工作流。
```

“去一个地方”只是外层形式。研究中的真实作品可能分别承担地方理解、个人回答、项目交付或现场调查。若只是想去山东拍好看，目前还缺一个能让这期成立的任务。

例如（以下三期都已有作品级研究支持，系列内部并不是同一模板）：

- 《去了一趟伦敦。》同时带有个人时间线与样片采集责任；
- 《去了一趟广西。》以地方、社区、人物和历史形成主体理解；
- 《去了一趟米兰。》把个人回答与地点限制的项目线放在一起。

## 9.3 指定某一期作品

```text
我想参考《1年150期视频？影视飓风2024工作流分享！》的任务和证据推进，不参考它的具体结论与文案。
```

Skill 会先确认你要参考：

- 创作任务 / 工作流；
- 结构与证据推进；
- 文字表达机制；
- 或它们的组合。

指定作品不等于复刻。正式支持的是创作方法、工作流、结构责任、证据组织和文本机制，不提供标题、原句、口头禅、镜头、音乐或字幕包装复制。

如果这期有作品级研究支持，Skill 能具体说明它要完成什么、哪些行动或证据推动了任务、有没有真正改变路线的转折、结论为什么只能到这个范围，以及哪些条件不该照搬。它不会把内部研究表格原样念给你。

## 9.4 标题片段与简称

你可以说“M1 那期”“激光打坏相机那期”“去一趟那个系列”。若能唯一匹配，Skill 会使用准确标题；存在多个结果时会列出 2–3 个候选让你选择；找不到时不会猜。

# 10. 研究覆盖是什么意思

索引覆盖 440 篇公开作品，但每一期被研究到的深度不同。用户不需要看数据库代号，只需要知道“因此可以可靠参考什么”。

| 当前研究情况 | 可以可靠参考 | 不会冒充掌握 |
|---|---|---|
| 只有基础作品覆盖 | 大方向、候选责任、可能的工作流 | 具体行动、转折、证据推进、该期文字机制 |
| 有作品级研究支持 | 任务、推进、关键行动/证据、真实转折、结论边界与迁移条件 | 仅凭文本确认镜头、剪辑、音乐或画质 |
| 部分判断有原文验证 | 被独立检查过的命题与边界 | 整篇作品都已完成深度结构研究 |
| 也进入过文字表达研究 | 已研究支持的文本功能与条件 | 逐句模仿、固定口头禅或人格复刻 |

如果只有基础研究，Skill 会直接说：

> 当前研究对这期主要做到基础作品识别。可以参考大方向，但我不会把没有深度研究过的具体结构说成确定规律。

如果没有作品级文字研究，Skill 仍可使用整体 Text Expression Model，但不会声称是在复现该期文案。

如果当前正式研究没有覆盖这期，Skill 不会停下：可以改用整体 Creator 方法、分析你提供的材料，或选择一部已有作品级研究支持的相近作品。用户临时提供材料所得的分析只属于当前会话，不会冒充既有 Creator Research。

# 11. 文字表达怎么用

## 11.1 保持自己的表达

```text
保留我的原口吻，只做普通的清晰度修改。
```

“只用创作方法，不要文风”“文字按我自己的”“只学创作方法”都属于这一档：不主动调用影视飓风 Text Expression，但仍允许修正明显语病、可读性和基础信息清晰度。

如果你说“不要改文字”“文字完全不处理”或“只分析结构，别碰我的文案”，Skill 才会完全关闭文字处理。

## 11.2 稍微加强

```text
文字表达稍微加强，重点做问题推进、参数到现实后果的翻译和结果限定。
```

## 11.3 明显加强

```text
文字表达明显加强，但不要加口头禅，不要改变事实、结构与结论。
```

## 11.4 文字层真正会做什么

- 建立这一段要解决的具体问题；
- 用问题、局部回答与新问题推进；
- 把术语和参数翻译成可感知后果；
- 每个证据单元及时说明“现在支持什么”；
- 把来源与限定放在对应主张附近；
- 按不同工作流改变文字责任；
- 把失败写成观察、缺口和修订。

真实语速、停顿、音色和剪辑节奏不属于文本研究。

# 12. 现实行动、实验、失败与负结果

## 12.1 什么时候值得行动

实验、采访、旅行、制作或资料研究至少应改变一项：

- 区分两个解释；
- 改变产品选择；
- 完成或验收一个交付物；
- 暴露职业技能与风险；
- 连接系统节点；
- 检验方法能否迁移；
- 加深对不可替代主体的理解。

只制造视觉刺激、不改变可知状态的行动，最多是表达素材。

## 12.2 失败不必被制造

失败只有在改变路线、方法、完成标准或结论强度时才进入主结构。没有失败也可以完成作品。

推荐写清：原本预期什么、实际看到什么、差距在哪里、因此改了什么、现在仍不能说明什么。

## 12.3 负结果也是结果

未观察到某件事，不等于证明它不存在。实验没有支持原假设时，可以这样要求：

```text
不要把负结果写成成功。说明它否定了什么、还不能否定什么，以及结论需要缩到哪里。
```

## 12.4 参数什么时候值得讲

至少要改变观众理解、用户行动、风险或可靠性、工作流成本、时间金钱人员、责任归属或最终判断。

# 13. 轻量作品

轻量不是敷衍。只要责任、必要证据、现实结果与结论边界闭合，一次小测试、一个窄问题或一个小成果都可以结束。

```text
这期保持轻量。若现有证据撑不起强结论，先缩小结论，不要自行增加采访、大实验或宏大背景。
```

只有当扩大方案能解决具体证据缺口，而且用户明确允许，才增加规模。

# 14. 什么时候写完整稿

完整旁白稿或脚本不自动生成。大纲、证据计划、采访问题、段落职责和局部示例不等于完整稿。

你提出完整稿或具体成文交付的请求，就已经授权相应范围。例如“写一版3分钟旁白”“把这些素材写成脚本”“替换第二段”都有效，不必再说固定口令；前两种可生成所请求的稿件，后一种仅修改第二段。

也可以只授权一部分：

```text
只写开头这一段，其他部分先保留结构。
```

停止时说：

```text
停止完整稿。回到任务、证据和结构。
```

# 15. 研究没有覆盖的内容怎么办

当前冻结研究没有系统覆盖：

- 镜头语言、景别、机位与运镜；
- 调色、视觉包装与字幕动画；
- 剪辑节奏与视觉转场；
- 配乐、音效与声音设计；
- 真实口播语速、重音、停顿与音色。

Skill 不会因为超出研究就停止帮助。它可以使用一般影视创作能力，或分析你提供的视频、截图、音频与时间轴，只会把来源分开说明：

> 工作流与证据组织有 Creator Research 支持；镜头和配乐方案来自一般影视能力。下面我把两部分分开给你。

用户提供的材料只服务当前任务，不会自动变成“影视飓风普遍规律”。

# 16. 如果它理解错了或状态漂移

## 16.1 直接纠正

```text
主线是产品判断，机制只做副线。保持轻量，不写完整稿。
```

## 16.2 重新对齐

```text
重新对齐当前项目。只总结当前目标、我明确锁定的要求、真实材料、输出权限和下一步，不要继续写。
```

## 16.3 项目恢复卡

```text
当前目标：
我已指定 / 锁定 / 禁止的要求：
已确认事实 / 已发生 / 计划 / 未确认 / 真实结果：
协作方式 / 完整稿 / 结构 / 文字偏好：
```

只有你明确指定的工作流、工作线或参考作品会随恢复卡保持。Skill 自己推断的工作流、研究覆盖、支持层、证据缺口和结论边界会根据当前目标与材料重新判断。

## 16.4 检查当前状态

```text
检查技能状态，不要开始创作。
```

普通协作会给短回执；进阶协作会显示完整中文控制面板。

以下是尚未给出项目和输出要求时的普通回执示例；已有要求时报告真实当前状态，不重置为示例默认值：

```text
创作方法：正常
文字表达能力：正常
协作方式：普通协作
完整稿：暂不生成
结构：可调整
内容规模：未锁定
文字：保持你的表达
```

普通状态不会显示冻结模型名称、覆盖代号或工作流编号。只有你明确要求“查看高级状态”“查看内部版本”或“调试 Skill”时，才显示这些内部信息。

# 17. 怎么安装

## 17.1 推荐：单文件版

只加载：

```text
dist/media-storm-creator-skill-v1.22.0-portable.md
```

它已经包含完整 Runtime 和内部作品覆盖索引。普通用户不需要加载其他文件。

## 17.2 模块化安装

把 `skill/` 整个目录复制到支持此格式的技能安装位置，目录命名为 `media-storm-creator`。保留 `SKILL.md`、六个编号模块和 `references/`。从 `SKILL.md` 进入，它会按任务读取必要模块；不能只复制六个文件而漏掉作品库。

手动加载时，先读 `SKILL.md` 和 `01_portable_instruction.md`。一般策划读 `02_domain_kernel.md`，需要详细路由再读 `05_decision_logic.md`；文字修改读 `03_product_policy.md`；反馈/恢复读 `04_runtime_state.md`；来源边界读 `06_research_boundary.md`。只有指定作品或核对证据时才读 references 内对应文件。

不要同时加载模块版与单文件版，避免重复指令。
