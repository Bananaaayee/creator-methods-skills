## 用户别名与内部路由

| 用户可调用名称 | 内部路由 | 最终责任 |
|---|---|---|
| 产品 / 工具适用性判断 | CR-W01 | 判断谁在什么场景该不该采用，以及代价和边界 |
| 机制解释与验证 | CR-W02 | 解释为什么 / 如何发生，证据支持到何种条件 |
| 项目实现与交付 | CR-W03 | 真正完成可验收成果，并交代约束、修订与成本 |
| 职业现场与劳动链 | CR-W04 | 理解真实工作、技能、风险、伦理与责任怎样连接 |
| 产业 / 公共系统调查 | CR-W05 | 解释多主体、资源、规则、利益和历史怎样构成系统 |
| 方法 / 机制拆解 | CR-W06 | 把作品、流程或机制转成可理解、可迁移的方法 |
| 主体理解 | CR-W07 | 对不可替代的自己、地方、人物或组织形成有边界的理解 |

这些是研究得到的创作责任分类，不是官方栏目、题材标签或固定叙事模板。

## 1｜产品 / 工具适用性判断

先问：谁用、在什么关键场景用、什么失败不能接受、替代方案是什么、最后要做购买/采用/部署中的哪种决定。

需要：对象、用户、场景、替代项、相关规格、真实使用或测试，以及样本与时间限制。技术信息必须翻译成现实收益、工作流成本、可靠性或兼容性后果。

推进：场景 → 决定性维度 → 测试/比较 → 取舍累积 → 条件性判断。

完成：指出适合谁、不适合谁、关键代价与未验证区域。多对象盘点仍属于本工作流的多对象模式，不另建工作流。

## 2｜机制解释与验证

先问：究竟解释什么、有哪些竞争解释、什么观察会支持或削弱它们、基线是什么、结论边界在哪里。

需要：现象定义、来源、案例、必要的演示或测试、对照、异常与限制。演示不自动等于验证。

推进：问题/异常 → 候选机制 → 证据/例子/测试 → 反结果/边界 → 修订后的解释。

完成：机制可理解，证据与反条件可见，未回答问题被命名。负结果可以完成解释任务。

## 3｜项目实现与交付

先问：必须交付什么、最低可接受结果、约束与不可逆节点、谁验收、哪些终点确实不可互换。

需要：Brief、成果定义、资源、计划、安全限制、尝试、修订、最终结果与验收证据。地点样片与自然窗口只是模式，不是新工作流。

推进：任务 → 约束 → 尝试/迭代 → 必要修订 → 交付 → 验收与成本复盘。

完成：说明最低交付是否达到、仍不完美的部分与实际代价。没有真实行动时不能伪装成已完成项目。

## 4｜职业现场与劳动链

先问：哪个岗位不可替代、能跟随什么真实任务、需要观察哪些技能和风险、谁能纠正外行理解、哪些不能外推。

需要：从业者、真实或明确受限的模拟任务、工序、交接、技能门槛、时间/身体成本、风险和伦理。

推进：进入任务 → 观察分工与技能 → 遇到约束/风险 → 从业者校正 → 有边界的职业理解。

完成：解释工作怎样做、为什么这样做、责任在哪里。一个人的经验不能自动代表整个行业。

## 5｜产业 / 公共系统调查

先问：系统边界是什么、哪些主体与缺失视角重要、人/货/钱/信息/权力如何流动、规则与历史怎样塑造后果。

需要：多个立场、现场节点或等价纪录证据、规则/法律/历史、数据、反证、来源记录与拒访/缺失记录。

推进：可见节点 → 依赖/下一主体 → 资源或权力链 → 规则/历史 → 后果和成本归属 → 明确缺口。

完成：形成可检查的系统机制。生动个案不能自动证明全国或全球普遍性。

## 6｜方法 / 机制拆解

先问：谁要使用、源自什么作品或实践、解决什么问题、关键输入/交接/选择是什么、哪里失效、什么可迁移。

需要：来源作品或生产案例、步骤与决策、输入输出、失败/替代、结果、受众条件和迁移限制。

推进：源问题/效果 → 机制或流程 → 决定性选择/交接 → 限制/失败 → 可迁移模型。

完成：别人能理解它做什么、按什么顺序、需要什么、适用到哪里。拆解既有作品与教人执行是两个模式，不是两个工作流。

## 7｜主体理解

先问：为什么这个主体不可替换、哪些时间/关系/观察/历史/行动能形成回答、什么矛盾不能压平。

需要：主体特定的时间线、旧今材料、行为与作品、关系、场景、访谈或观察，以及明确局限。

推进：初始未知 → 主体特定材料与相处 → 矛盾/修正 → 有边界的理解。

完成：回答这个自己、地方、人物或组织是谁/如何形成。抽掉主体后结论仍成立时，优先考虑方法拆解而非主体理解。

## 跨任务 Creator Mechanisms

### 责任先于形式

按最终不可替代责任路由。标题、开场钩子、栏目、地点、采访对象和外层形式只是候选信号。

### 规模与责任成比例

窄问题不自动升级为大制作。研究、设备、地点和人数只在改变结论或完成度时增加。

### 承担论证的行动应改变可知状态

在解释、评测、调查和需要论证的项目中，相关行动应区分解释、改变判断或收窄边界；项目交付也可以由实际成果与验收完成。娱乐、感官交付和纯展示不必承担因果证明，可以由可观察体验、互动、成果和局部结算完成，不强加实验或证据表。该限定恢复既有07C验证集C-05的适用范围；新增反例见C-S14/C-S15。

### 证据来源保持可见

区分官方/品牌说法、用户材料、直接测试、长期经验、受访者陈述、数据/外部研究和推断。不要把不同来源悄悄合并。

### 失败、负结果与缺口是信息

失败只有在改变路线、验收、解释或结论时才是结构节点。未观察到不等于证明不存在。

### 技术信息服务当前责任

只保留会改变理解、选择、行动、风险或结果的参数和术语。先给最小定义，再翻译成可感知后果。

### 结论强度服从证据规模

把时间、对象、样本、环境和团队条件放在相关主张附近。大结论需要相匹配的证据链。

### 轻量是合法完成方式

轻量不是敷衍。只要责任、必要证据、现实结果和结论边界闭合，作品可以很小。

## Mixing / Shift

- 单一主线：所有材料共同完成一个责任。
- 主线 + 副线：副线解释、补证或增加理解，但不承担最终验收。
- 双线并行：两条线各自有问题、证据、推进与结果；不能只靠章节分隔冒充双线。
- 主线转移：新的现实结果让最终问题、证据、推进和结论责任共同变化。

表达方式、采访出现、幽默、地点变化或阶段总结都不能单独证明主线转移。

## Text Expression Frozen Rules

### 五条核心机制

1. 先建立“这段要解决什么”的具体合同。
2. 用“问题—局部回答—新问题”推进，不只靠章节宣布。
3. 把事实、参数和术语翻译成可感知后果。
4. 每个证据单元就地结算，不把所有判断拖到结尾。
5. 叙述立场随证据来源切换，并把来源留在句面上。

### 条件机制

按七个工作流分别调整文本责任：产品判断逐项重开决定性维度；机制解释走最短解释链；项目线保持目标、约束、修订与交付同线；职业线让工序与责任校正外行疑问；系统线沿主体、流向、规则与代价追链；方法线带适用对象、分支与例外；主体线允许问题晚显形，但用具体场景承担个人回答。

失败写成“观察—缺口—修订”；经验与测试结论就近限定。幽默、短长句、固定开场、口头禅和标题词频都不是冻结规则。

## VN20261025｜把既有方法落实到项目

以下为本轮原文核对后的**运行建议**；不是作者公开声明的完整思考流程，也不表示影视飓风独有。证据、反例和支持范围见 [evidence-vnext.md](references/evidence-vnext.md)。

### 先判断现场能否预设，再决定问题何时锁定（C-VN01）

七种最终责任之外，另看材料的可控程度：

- 讲述、产品比较、可重复演示：先拟一个观众真实关心、可被证据改变的窄问题；片名/开头的承诺必须能被后文兑现。没有观察前只写候选判断，不预写成功或失败。
- 旅行、人物相处、现场事件：先定观察方向、访问条件和记录方法；可以准备可调整的规则，不能预设人物反应、矛盾或人生答案。已有素材时从发生的事件反推主题，允许原问题被撤销。
- 混合项目：技术测试可预设协议；人的回答保持开放。分别处理，不能因为同一条片里有测试就预设所有现场。

这是独立于题材的决策轴，不把“现场”误当成第八工作流。原文自述《2024工作流分享》明确承认“壳”方法在随机现场的局限；《米兰》也不宜改成从头证明一个休息理论的实验片。

### 选题是否需要影像回答（C-VN02）

给选题建议时，说明这个具体对象让观众多知道或能做什么，以及哪种**可取得的差异/动作/现场材料**能完成回答。若参数表已经回答全部问题，优先做简短信息说明；若只有漂亮画面，可做样片/观察记录，接受用户只想展示的目的。不要强造社会意义、实验、购买建议或宏大命题。

标题与切点可以暂定；出现证据反驳时改承诺，不让结果服从标题。投入的设备、地点与人员只有在观众能理解其作用时才扩张。

### 区分四种材料责任（C-VN03、C-VN04）

| 材料 | 能负责什么 | 不能直接推出什么 |
|---|---|---|
| 产品展示/操作演示 | 有什么、怎样操作、某次实现了什么 | 普遍可靠、胜过竞品、适合所有人 |
| 条件明确的测试/对照 | 在这些设置、样本、任务中的差异与代价 | 未测场景、长期故障率、唯一因果解释 |
| 机制论证 | 用资料、对照或可区分替代解释的观察连接原因与后果 | 仅凭一个好看的例子就确认机制 |
| 真实场景样片/使用记录 | 该团队在给定制作条件下取得的结果、使用摩擦 | 设备单独造成效果、普通用户必然复现、所有视觉指标已获量化 |

品牌规格、受访者说法与使用者感受在上述材料旁保留来源。赞助展示不能悄悄变成独立测试，采访承诺不能变成已经落实的事实。字幕只能确认作者描述过这些行动；没有画面/原始测量，不能替作品验收画质或复核数值。

### 做得出且能改变判断的最小测试（C-VN03）

只为当前选择设计必要项目。每项交代：要改变哪个决定；比较对象/基线；关键设置与会混淆结果的条件；记录什么；什么结果会让建议改变。无需把五项机械打印为表格，短请求用自然语言完成。

用“拍得到/持续拍得稳/后期交得出”检查生产工具的链路，只测与用户任务有关的环节。产品不同，权重不同：轻稳定器可以只围绕轻与稳；12K设备的存储、回放、导出成本可能比最高分辨率更能改变采用判断。不得把这三个环节一律扩成全面深评。

主观喜好可以保留为本人的体验，不能以职业参数否定体验用户。《评测问题》中作者承认性能与体验人群目标不同，但这是一篇自述，不能据此宣称所有消费者只有两类。

### 让观众能读懂证据，再增加信息（C-VN05）

结构或旁白建议应把决定性信息接到能被理解的后果：这个差异回答哪一问，观众需要看到/知道哪一项对照，现在能下多大的判断。密集技术段后，用必要的局部结算帮助理解；不按固定秒数插梗，不给每段强加反问或总结。

当判断依赖观看介质、放大倍率、场景或交互条件，应把条件靠近判断；普通发布链路无法显示该差异时，明确限制，改成有说明的放大对照、测量图或降低结论。具体镜头/图表形式属于一般制作建议，不能冒称已验证的创作者视觉风格。

个人观察、记忆联想和纯展示可以保留开放感，不要求逐段形成评测结论。《米兰》是反例边界。

### 已拍素材先结算，用户反馈按影响范围修（C-VN06）

用户带真实材料时，先分出“可直接支持主张 / 只提供氛围或个人体验 / 仍缺证据”。缺测项缩小结论；可用很小补拍补足时再建议，不把未拍经历编进稿。只有计划时，输出拍摄/测试计划，不能用过去时伪装完成。

用户说“太重/不像我/只改这一句”时：撤销被否定的推断或文字做法；保留事实与未被否定的约束；直接在授权范围内给修改。解释本次改动如何解决反馈即可，不重新输出整套方法，不要求重复确认，不把已撤销判断偷偷带回。新证据推翻主张时，同步改该段和受影响结尾；若结构已锁定，先给局部可行版本与明确的未解决断点。
